# Your AI Assistant Should Tell You Which Model Answered

## Model identity and message-level provenance should be ordinary parts of enterprise AI

When an AI assistant gives an answer, the interface often presents it as though “the assistant” were a stable individual. Behind that simple label, however, the provider, model, prompt, retrieval source, and available tools may all have changed.

That matters in enterprise work. If an answer contributes to a design decision, risk assessment, policy interpretation, or implementation plan, “the AI said so” is not adequate provenance.

At minimum, a user should be able to discover which provider and model produced each substantive response.

## The model is part of the evidence

Different models have different capabilities, limitations, context windows, tool-use behaviour, and reliability. Even two versions from the same provider may respond differently to the same evidence.

Organisations routinely record the author and version of an important document. AI-generated material deserves similar treatment. A useful response record might include:

- Provider and model
- Date and time
- Knowledge sources retrieved
- Tools used
- Relevant model or prompt configuration
- The user or process that requested the work

This does not require displaying technical metadata beside every sentence. A compact “Response details” control is often enough. The normal conversation remains readable while reviewers can inspect provenance when it matters.

NIST describes accountability and transparency as connected characteristics of trustworthy AI and notes that meaningful transparency should provide information appropriate to the people interacting with the system. [NIST AI Risk Management Framework](https://airc.nist.gov/airmf-resources/airmf/3-sec-characteristics/)

## Preserve provenance at the message level

Recording only the assistant’s current default model creates a subtle historical error.

Imagine that an organisation begins with Model A, later changes its default to Model B, and then opens a six-month-old conversation. If the interface now labels every old response as Model B, it has rewritten history.

The model identity should therefore be recorded when each response is created. Changing the default should affect future responses, not the provenance of previous ones.

This also supports deliberate model switching. A user may ask one model to draft an assessment and another to challenge it. Both contributions can live in the same conversation as long as their identities remain attached to their respective messages.

## Generation and retrieval are different

A response may be generated by one model while relying on embeddings or retrieval produced by another. The conversational model and embedding model should not be presented as though they were the same role.

Similarly, changing the conversational model should not silently alter the knowledge index. Administrators need to understand which model performs which job, and users need enough information to interpret the output appropriately.

## Transparency is not chain-of-thought disclosure

Useful transparency does not require exposing hidden reasoning or internal chain-of-thought. It means showing meaningful operational facts:

- The system is searching approved organisational knowledge
- It is checking available evidence
- It used a named tool or data source
- A particular model generated the completed response

The OECD AI Principles call for responsible disclosure so people understand when they are interacting with AI, its capabilities and limitations, and—where appropriate—the factors or inputs behind an outcome. [OECD transparency and explainability principle](https://oecd.ai/en/dashboards/ai-principles/P7)

## Provenance does not make an answer correct

A detailed label can still accompany a poor answer. Provenance is not a substitute for evaluation, source review, or human judgement.

Its value is more basic: it makes the answer inspectable. It helps people reproduce a test, compare models, investigate a failure, and understand which configuration influenced an important artifact.

The goal is not to turn every conversation into an audit report. It is to ensure that when an AI contribution becomes important, its origin has not already been lost.

In an evidence-led AI enterprise, model identity should not be a developer-only detail. It should be part of the record.
