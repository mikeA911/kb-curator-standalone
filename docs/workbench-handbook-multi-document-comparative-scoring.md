# Multi-Document Comparative Scoring

**Proposed Wiki category:** Workbench Handbook (`platform_handbook`)
**Proposed slug:** `multi-document-comparative-scoring-workbench-method`
**Proposed status:** Draft -> human review -> approved
**Audience:** Procurement practitioners and anyone comparing vendors, products, or tools against a
common requirement set

## What it is

Multi-Document Comparative Scoring is a Workbench method for scoring and comparing multiple
candidate documents -- vendor proposals, vendor products, tools -- against one common requirement
set. It is distinct from AI Strategy Comparison and AI Model Evaluation, which compare *approaches
or models* against a task; this method compares *documents* (what candidates claim, in writing)
against a fixed requirement set.

## Why it matters

A side-by-side vendor comparison is only fair if every candidate is scored against the same
requirements, in the same way -- not against each other's own framing of what matters. Making the
requirement set the fixed reference point, rather than letting each proposal set its own terms of
comparison, is what keeps the result defensible.

## Requirements

**Required:** the requirement set (an RFP or specification); two or more candidate documents.

**Optional:** a weighting or scoring rubric.

**Git required:** No.

## Method

For each candidate, extract its claims against each requirement, score coverage and fit, and surface
gaps or risks a human reviewer should specifically check. Rank the candidates against the common
requirement set -- never against each other's marketing framing.

## Deliverables

A Comparison Matrix; per-candidate Scoring; a Gaps/Risks list; a Recommendation.

## Boundary

KB Sandbox scores based on the evidence each candidate actually submitted. Procurement, or whoever
owns the decision, makes the award -- this method surfaces the comparison, it doesn't decide.
